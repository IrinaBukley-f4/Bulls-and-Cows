# Design Document: Bulls and Cows

## 1. Структуры данных и алгоритмы

В проекте используются иммутабельные структуры данных, чтобы избежать побочных эффектов и упростить тестирование. Игровая логика полностью отделена от DOM и представлена чистыми функциями.

### Состояние игры (`src/state/gameState.ts`)
Для хранения состояния используется интерфейс `GameState`:
* `status`: `'setup' | 'playing' | 'won'` — текущий экран.
* `length`, `base`: настройки раунда.
* `secret`: секретное число в виде строки (это позволяет корректно обрабатывать лидирующие нули, например `'0123'`).
* `history`: `readonly Attempt[]` — история попыток. Использование `readonly` на уровне типов гарантирует, что массив не будет изменён мутационно (через `push` или `splice`). Каждая новая попытка создаёт новый массив через spread-оператор: `[...s.history, newAttempt]`.
* `startedAt`: время начала раунда для подсчёта таймера.
* `attempts`: количество сделанных попыток.

### История попыток (`Attempt`)
Каждая запись содержит: саму попытку (`guess`), результат (`bulls`, `cows`) и временную метку (`timestamp`). Старые записи никогда не изменяются и не удаляются, что соответствует требованиям.

### Алгоритм `evaluateGuess` (`src/core/evaluateGuess.ts`)
Функция вычисляет быков и коров за два прохода с использованием методов массивов (`reduce`, `filter`), без ручных циклов.
1. **Быки**: через `reduce` сравниваются символы на одинаковых индексах.
2. **Коровы**: сначала создаётся счётчик вхождений цифр в секрете (`secretCounts`). Затем через второй `reduce` проходятся по попытке. Если цифра не на своём месте (не бык) и её счётчик в секрете больше нуля, она засчитывается как корова, а счётчик уменьшается. Это корректно обрабатывает повторы в попытке (хотя по правилам игры они невозможны).

### Алгоритм `countPossibleSecrets` (`src/core/countPossibleSecrets.ts`)
Функция считает количество перестановок без повторений: \(P(base, length) = \frac{base!}{(base - length)!}\).
* Реализована **рекурсивно** на основе формулы: \(P(n, b) = b \times P(n - 1, b - 1)\).
* Базовые случаи: если \(n > b\) или \(n < 0\), возвращается `0`; если \(n = 0\), возвращается `1`.
* Для оптимизации используется **мемоизация** через `Map`. Ключ формируется как `${length}:${base}`. Для тестов экспортируется функция `clearMemoCache()`.

## 2. Сложность (Big O)

* **`generateSecret(length, base, random)`**: 
  * **Сложность**: \(O(length^2)\).
  * **Обоснование**: На каждом шаге рекурсии мы выбираем случайный индекс и удаляем элемент из пула через `filter`. Фильтрация массива пула занимает \(O(k)\), где \(k\) — текущий размер пула. Сумма по всем шагам: \(base + (base-1) + \dots + (base-length+1)\), что в худшем случае (при \(length \approx base\)) даёт \(O(base^2)\). Так как \(length \le base\), сложность можно записать как \(O(length^2)\).
  
* **`evaluateGuess(secret, guess)`**:
  * **Сложность**: \(O(n)\), где \(n\) — длина секрета.
  * **Обоснование**: Два прохода по массивам длины \(n\) (один `reduce` для быков, второй `reduce` для коров). Создание `Set` для счётчика также занимает \(O(n)\). Константные множители отбрасываются.

* **`isValidGuess(guess, length, base)`**:
  * **Сложность**: \(O(n)\), где \(n\) — длина строки (или `length`).
  * **Обоснование**: Проверка длины \(O(1)\). Приведение к нижнему регистру и создание массива символов \(O(n)\). Проверка каждого символа через `createDigitValidator` (использует `Set.has`, \(O(1)\)) занимает \(O(n)\). Проверка уникальности через `new Set(chars).size === chars.length` занимает \(O(n)\).

* **`countPossibleSecrets(length, base)`**:
  * **Сложность**: \(O(length)\) для вычисления (с мемоизацией).
  * **Обоснование**: Благодаря мемоизации каждое уникальное состояние `(length, base)` вычисляется только один раз. Глубина рекурсии равна `length`. Без мемоизации сложность была бы \(O(2^{length})\) из-за дублирующихся вычислений, но с `Map` мы достигаем линейной сложности по количеству уникальных пар, что в данном случае ограничено \(O(length)\).

## 3. Принципы чистого кода

В проекте применены следующие принципы из модуля Clean Code:

1. **Чистые функции (Pure Functions)**:
   * *Где*: `src/core/*.ts` (все игровые функции).
   * *Как*: Функции не зависят от внешнего состояния, не мутируют аргументы и не имеют побочных эффектов. Например, `evaluateGuess` только возвращает объект `{ bulls, cows }`.

2. **Инъекция зависимостей (Dependency Injection)**:
   * *Где*: `src/core/generateSecret.ts`.
   * *Как*: Источник случайности передаётся параметром `random` (по умолчанию `Math.random`). Это делает функцию тестируемой с детерминированным генератором (например, `() => 0`).

3. **Иммутабельность (Immutability)**:
   * *Где*: `src/state/gameState.ts`.
   * *Как*: Вместо `push` используются spread-операторы: `[...s.history, attempt]`. В интерфейсе `history` помечен как `readonly Attempt[]`.

4. **Функции высшего порядка (HOF)**:
   * *Где*: `src/core/evaluateGuess.ts`.
   * *Как*: Вместо циклов `for` используются `reduce` и `filter`. Это делает код более декларативным и коротким.

5. **Каррирование (Currying)**:
   * *Где*: `src/core/createDigitValidator.ts`.
   * *Как*: Функция `createDigitValidator(base)` возвращает предикат `(char) => boolean`. Это позволяет переиспользовать логику валидации в `isValidGuess` и в UI-фильтре ввода (`main.ts`) без дублирования кода.

6. **DRY (Don't Repeat Yourself)**:
   * *Где*: Валидация цифр.
   * *Как*: Логика проверки «является ли символ допустимой цифрой» вынесена в `createDigitValidator` и используется как в ядре игры, так и в обработчике `input` в `main.ts`.

7. **Единая ответственность (SRP)**:
   * *Где*: Структура проекта.
   * *Как*: `src/core` — только вычисления, `src/state` — хранение и обновление состояния, `src/ui` — рендеринг DOM. `main.ts` — только склейка (composition root).

8. **Отсутствие магических чисел**:
   * *Где*: `src/core/createDigitValidator.ts`.
   * *Как*: Строка `DIGITS = '0123456789abcdef'` вынесена в константу. В `main.ts` константы для ключа `localStorage` и лимита записей.

9. **Безопасный рендеринг**:
   * *Где*: `src/main.ts`.
   * *Как*: Для создания элементов используется `document.createElement` и `textContent`. Запрещённый `innerHTML` не применяется для динамических данных (только для очистки контейнера перед полной перерисовкой, что безопасно).
